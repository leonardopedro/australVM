L10 Cycle A: emit a real Why3 theory, and share one Why3 with unfer

Two things, because the second is what made the first checkable.

## Sharing the engine (no more duplicate Why3)

unfer already used Why3 (S36: `uk_whyml_emit` shells out to `why3 prove` and
`why3 extract`), so adding it to australVM was on track to create a second copy.
It had: the flakes sit on different channels, and a different nixpkgs revision
means a different store path, so nix could not dedupe.

  before   australVM  nixos-unstable  34ab990…  why3 1.8.2
           unfer      nixos-23.05     70bdade…  why3 1.6.0
  after    both                    70bdade…  why3 1.6.0   (one store path)

This was worse than the disk cost: each project was validating `.mlw` files with
a *different* engine, so a file one prover accepted could be refused by the other
with no obvious cause — and `LiquidWhy3.prove` maps exit codes onto
Proved/Refused, so it would have surfaced as a mysterious contract rejection in
one project only.

australVM cannot move its base channel to 23.05 (its own flake documents why:
the cranelift bridge needs a newer rustc, and a 23.05 binary cannot load an
unstable-built `.so`). So it keeps nixos-unstable for its toolchain and takes
unfer's channel as a separate `why3-nixpkgs` input used *only* for why3 and
alt-ergo — the shared store path without touching the bridge. unfer's flake
documents the coupling and what breaks it.

This also corrects a mistake of mine: I had used `alt-ergo-free` because
`alt-ergo` is unfree and I would not flip that policy unilaterally. But unfer
already sets `allowUnfree = true` for CUDA, so the two would have used
*different provers*. `allowUnfree` is now scoped to the Why3 import and both use
the real alt-ergo.

## Cycle A: `emit_theory`

The `.mlw` previously declared **no functions at all**, so every goal was closed
over bare parameters and a caller had nothing to appeal to. It now emits the
module's total-fragment functions as a Why3 theory:

    function atLeast (n: int) : int
    axiom atLeast_post: forall n: int. (n >= 0) -> atLeast n >= n

The shape was established by running the engine, not by guessing, and two of my
first three attempts were wrong:

  * a bodyless `function ... requires/ensures` is a **syntax error**;
  * a `val` does not bind its name for use in a goal's formula **at all**;
  * what works is a bare `function` declaration plus an `axiom` over the symbol.

The axiom is an **assumption, not a proof** — it states what the function is
declared to do so callers may rely on it. Same conservative shape L6 uses for
qualifiers: an undischarged obligation stays visible in the file. Proving it
needs the function body, which is not translated.

Checked that the theory is not vacuous: a caller goal that uses the axiom comes
out `Valid`, and one that *overstates* the contract does not.

**What remains, now visible.** The RETURN goal is still
`forall n, __result: int. n >= 0 -> __result >= n`, and `__result` is
unconstrained because function bodies are not translated, so the goal is sound
but underivable — Why3 returns `Timeout`, not `Valid`. Previously this was
hidden behind a syntax error. Closing it means translating the body; that is the
remaining L10 item.

Verified: verify-invariants 17 passed / 0 failed (including the Why3 parse gate
on the goldens), 9 dune suites green, all test-programs pass. Goldens confirmed
to parse under both Why3 1.6.0 and 1.8.2, and the exit-code mapping is sound
under the shared version.
