Share one Why3 with unfer — on the version the existing driver needs

Follow-up to installing Why3 here. unfer already ran it (S36:
`uk_whyml_emit` shells out to `why3 prove` and `why3 extract`), so adding it to
australVM was on track to build a second copy — and it had: different nixpkgs
revisions mean different store paths, so nix could not dedupe.

  before   australVM  nixos-unstable  why3 1.8.2   sglqns…
           unfer      nixos-23.05     why3 1.6.0   wsh74n…

Both now resolve `why3-1.8.2` and `alt-ergo-2.6.3`: one build, one version, one
`~/.why3.conf`. Neither flake changes its own base channel — australVM must stay
on nixos-unstable for the cranelift-bridge glibc constraint, unfer on 23.05 for
CUDA — so the toolchain is pinned by revision on each side instead. Pinned by
revision rather than by branch on purpose: a floating `nixos-unstable` would let
the two flakes drift apart again the next time the channel advances, silently.

**The version is 1.8.2 because the existing driver requires it, not because
australVM happened to have it.** `lib/why3_plugin/unfer_ocaml.drv` maps
`bool.Bool`'s `=`, which exists in Why3 1.8.x and does not exist in 1.6.0:

    $ why3 extract -D unfer_ocaml.drv authorize_gate.mlw -o out.ml   # 1.6.0
    Unknown val bool.Bool.infix =

So unfer's extraction path was **already broken on unfer's own channel**, and
still exits 0 while failing — the same false-success shape as the missing-prover
case. Aligning to 1.8.2 fixes that rather than preserving it. I checked that
unfer's result parsing is version-agnostic first: `whyml.rs` counts lines
containing `Valid` and rejects on `Invalid`/`Failure`/`Timeout`, so it does not
depend on 1.6-era output formatting. Its whyml tests pass under 1.8.2.

Verified after the change: `why3 extract -D unfer_ocaml.drv` succeeds (388-byte
output, the case that failed on 1.6.0), alt-ergo is now 2.6.3 so Why3 no longer
warns about an unrecognised prover version, both repos resolve byte-identical
store paths, australVM's Why3 parse gate passes, 9 dune suites green,
test-programs pass, unfer_ffi 113 and prob_kernel 53 tests pass.

Also carries L10 Cycle A: the emitter now writes a Why3 theory so a caller can
appeal to a callee by name, using a `function` declaration plus an `axiom` —
the two shapes I tried first (a bodyless `function` with its own contract, and a
`val`) are respectively a syntax error and a symbol that never binds. The axiom
is an assumption, not a proof, and the test confirms it is not vacuous: a
caller that uses it comes out Valid, one that overstates the contract does not.
