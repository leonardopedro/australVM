# Parallel execution for Bend and Austral on SafestOS

**Proposed, 2026-11-20.** SafestOS owns jobs, placement, capabilities and
resources. The existing CPS/Cranelift bridge compiles CPU code for both
frontends. The existing WGSL/wgpu path and the planned MLIR/device backends
compile accelerator code from the same admitted computation. SafestOS can
dispatch to each backend through its host service. BendRT supplies a design
reference and a comparison implementation. The shared CPU and accelerator
release tests run with the Bend runtime absent. This plan supplies the
parallel-execution tasks for [BI05, BI08 and BI10](../PLAN_bend_austral_integration.md#implementation-cards)
and continues [Liquid R3](LIQUID_BEND_PLAN.md#r3--use-the-existing-forkjoin-candidates-and-gpu-roadmap).

## What to reuse

| BendRT technique | SafestOS implementation direction |
| --- | --- |
| Compile tail calls, non-tail call continuations, and forks into distinct execution paths. | Reuse the bridge's self-tail loop. First outline admitted pure child blocks and joins into named CPS/Cranelift functions. Use a small typed frame for captures and results. Add native tail calls only for verified compatible internal signatures and targets. |
| A fork gives each child a result slot. An arriving child can trigger its parent continuation when the other slots are ready. | Give each fork two indexed result slots and one runnable join generated by the host. Store results by index so completion order leaves application results and failure priority deterministic. Free the frame once join and cancellation obligations are settled. |
| Balanced forks use bounded per-lane queues and a grow/work frontier. An imbalanced tree can leave lanes idle. | Start with bounded CPU worker queues and fixed tiling for range work. Measure balanced and skewed fixtures. Try chunked frontier batches first for predictable work and bounded work stealing only if skew merits it. Reuse workgroup tiling and multi-dispatch passes on GPU. |
| Affine use enables scoped allocation, inferred borrows, reuse of unique storage, and counting where sharing is needed. | Reuse Austral ownership and split witnesses, Bend live-use information where reflected, and SafestOS regions. Admit reuse only with an ownership proof. Start with scalar captures and disjoint buffers. Add optional retained immutable data after measuring task/frame allocations. |

BendRT's equal-parts assumption is a performance premise. Its paper also
describes separate CPU and GPU phases and an unverified C runtime. Treat
overlapping CPU/GPU work as a separate SafestOS scheduling target. Use Bend's
balance ideas for placement while checking safety for skewed tasks too.
[BendRT §§3–7 and 12](https://github.com/bendlang/bend/blob/0e2f38f759cc830849e489307f3d256a7d148288/paper/BendRT.pdf),
[pinned compiler](https://github.com/bendlang/bend/blob/0e2f38f759cc830849e489307f3d256a7d148288/bend2/comp.ts).

The bridge already emits a restart-block jump for direct self-tail calls.
Its general `emit_return_call` currently emits a call followed by return.
The JIT is thread-local, and `cranelift_swap_binary` invalidates previous raw
entry pointers. The older C pause queue spins when full and lacks slot
reservation for multiple producers or consumers. The GPU
service has linear job receipts and completion callbacks, and currently
spawns a worker thread for each non-mock submission. Reuse the available
compiler, slot and lifecycle abstractions at their current scope. These
details determine where the parallel extension starts.
[CPS lowering](../safestos/cranelift/src/cps.rs),
[JIT bridge](../safestos/cranelift/src/lib.rs),
[C pause queue](../safestos/runtime/scheduler.c),
[GPU service](../safestos/gpu/src/service.rs).

## Implementation cards

### SP00 — Run one serial Cranelift workload from both frontends

**Depends on BI02 and BI05's CPU code generation.** Start with a pure U32
mapper over a bounded immutable input range and an explicit modular map-and-sum.
Reuse G22a's exact arithmetic, partition model, and serial oracle. Start with
one mapper or bounded leaf per Cranelift entry. Use checked scalar/status
arguments and the existing typed host ABI. Extend the ABI for a checked
buffer view only if the scalar fixture proves the path first. Use the
existing JIT to run the leaf and `capture.rs` to derive its byte and
relocation records from the same lowering. Pin the actual CPU target and
features. Leave safepoints, resource checks and proof gates on the host side.

**Exit.** Both source fixtures feed the same Cranelift compilation and run
through `modhost` or its existing `ModuleHost` API in tests. Compare equal
outputs and common semantic inputs under the same target/capture configuration.
Empty, singleton, ragged and U32 wraparound cases agree with the independent
oracle. Changing signedness or the input/output ABI fails a control.
[G22a](gpu/NEXT_STEPS.md#g22a--define-map-and-sum-and-check-its-cpu-schedule),
[module host](../safestos/cranelift/src/module.rs),
[native code capture](../safestos/cranelift/src/capture.rs).

### SP01 — Add bounded CPU submission and safe code lifetime

**Depends on SP00 for integration.** Add a small CPU executor to SafestOS's
existing module host and expose it through the job lifecycle used by BI08.
Start with a fixed worker count and bounded queue, with a maintained Rust
queue implementation if an existing one fits. Make `try_submit` return
`Busy` before transferring ownership if no slot can be reserved. Let idle
workers sleep. One worker initially owns its own compilation and invocation
in the bridge's current thread-local JIT. Scale this to a fixed set of
workers compiling once per artifact and generation. Queue opaque entry IDs
and owned data, with raw pointers resolved by the owning worker at dispatch.
Pause submissions to a retiring generation and let its queued and running
jobs drain or cancel before resetting or swapping its JIT. Record compilation
cost and memory per worker. Consider shared executable mappings only after
the loader can hold them for every outstanding execution and relocation.

Bind each job's principal, generation and budget at admission. Authenticate
submit, poll, cancel and result collection with the host's context. Restrict
the first native leaf to the checked pure subset. Before adding effectful
worker calls, complete the context-bearing authorization work in the
distributed plan. The bridge's legacy deployment principal reflects the
most recently loaded manifest. A worker cannot infer its authority from it.

**Exit.** With a worker deliberately held, an authorized client can submit
up to the limit, gets `Busy` promptly at capacity, and can still poll or request
cancellation. A second client cannot operate on the first client's receipt.
Pause a job, request a swap, and prove via the test trace that its code,
captures and generation remain valid until retirement. Include late
completion, worker error with no result, and repeated collection. Compare one
and two worker runs. [Job contract](gpu/G15_DESIGN.md),
[existing authorization state](../safestos/cranelift/src/auth.rs),
[distributed runtime plan](../PLAN_distributed_security.md).

### SP02 — Compile one structured fork and join through the CPS bridge

**Depends on SP01 and the split obligation from Liquid R3 or G22a.** Lower
one enclosing computation into two named pure child functions and one join
function. Use an enumerated entry or compiler-issued identifier and a typed
frame of immutable captures and indexed result slots. Initially pass scalar
values or read-only ranges. Admit disjoint, owned output spans once the split
certificate covers the exact ranges. Use a host join transition to enqueue
the join exactly once after both child results are visible. Give a child
failure or cancellation an explicit terminal path. A worker executes ready
tasks and returns to its loop when a fork suspends, allowing a single worker
to make progress through nested forks. At admission reserve the first fork's
child/join capacity, or run an equivalent bounded pure branch inline according
to the profile. An authentication or resource failure returns an error.

Reuse `Compiler_cps.ml`, `CpsGen.ml`, `cps.rs` and the existing ABI where
possible. A new CPS opcode needs an identified missing operation plus updates
to `Cps_codec`, `ISA_REGISTRY`, decoder tests, and the MM0 instruction census.
Expose the same primitive to Bend's checked fork form and Austral's checked
R3 operation via BI02's admissions. Keep the task descriptors and host calls
identical downstream.

**Exit.** With BendRT absent during execution, both inputs reach the same
Cranelift child and join bodies and the same SafestOS job interface. Measure
actual overlap of independent children with two workers, and completion
without deadlock with one worker and a small queue. A deliberately noncommutative
join catches a swapped child slot. Tests inject late and duplicate completions,
one-child failure and cancellation during a join. A queue-capacity mutation
cannot strand a frame or publish twice. [CPS entry](../lib/Compiler_cps.ml),
[CPS codec](../lib/Cps_codec.ml), [ISA census](../scripts/isa-census).

### SP03 — Measure and optimize the common CPU backend

**Depends on SP02.** Land optimizations individually. In order:

1. Batch small leaves, set an explicit size threshold for inline work, and
   compare contiguous chunks with the baseline queue. At every supported
   size, split witnesses must still cover each element once. A fixed two-slot
   frame can start in bounded job storage. Reuse frames after all children and
   the join retire. Measure region or per-worker slab allocation before adding
   cross-worker memory reuse. A job result must outlive the region it escapes.
2. Convert a bounded closed cycle of internal continuations into one loop or
   trampoline if profiling shows call or stack costs. Prefer the existing
   self-tail path for self calls. Experiment with Cranelift `return_call` only
   on pinned targets with compatible internal calling conventions and matching
   signatures, including stack arguments. Stable host calls retain their
   current ABI. Exercise deep mutual recursion and inspect the emitted code
   for bounded stack use. [Cranelift instruction contract](https://docs.rs/cranelift-codegen/latest/cranelift_codegen/ir/trait.InstBuilder.html#tymethod.return_call).
3. Measure balanced and skewed trees. Try chunked per-worker frontier batches
   for regular siblings. If skew leaves workers idle, compare bounded stealing
   using an existing deque implementation. Keep the same queue budget and
   cancellation semantics. Add buffer reuse or fused leaf loops only where
   checked ownership and numeric rules permit them. Offer SIMD for the measured
   loop as a later Cranelift optimization with an independent scalar oracle.

**Exit.** Each accepted optimization matches the sequential oracle and has
one before/after measurement under pinned compiler and host settings. Use a
serial Cranelift baseline and the pinned Bend backend on equivalent supported
fixtures. Measure one and multiple CPU workers, median and tail latency,
throughput, allocation counts, queue high-water mark, compilation cost and
resident memory. Record the crossover by task size and behavior on skewed
trees. Keep faster policies behind a selectable profile until the evidence
supports a default. [Region API](../safestos/runtime/region.c).

### SP04 — Carry a parallel proof across the SafestOS and Cranelift boundaries

**Starts with SP02's task semantics.** Apply PC03/PC08 to the selected CPS,
CLIF, native child and join bodies, and actual capture/relocation records.
Use PC13's event and resource model for the scheduler. State determinism under
valid completion schedules, disjoint writes, one-time collection, and
reclamation after the last user. Compose the shared pure proof with fork and
join rules. Record the atomic publication and visibility obligations at the
queue or join edges. Begin with deterministic interleaving tests and a small
MM0 event model. Close the implementation-to-model edge separately using
checked transitions and a memory-model argument. Keep unobserved host/runtime
steps explicit until that edge closes. State progress under explicit fairness,
capacity and bounded-child assumptions.

**Exit.** Both frontends reuse one parallel theorem and the same checked
runtime/backend edges. Mutations for duplicated join, publishing a result
before its slots are visible, overlapping outputs and retirement during a live
call fail the relevant checks. Publish the deepest proof cut, including any
remaining queue or memory-model assumptions.
[PC08 and PC13](lean4mm0.md#pc08--connect-one-actual-cpu-instruction-fragment).

### SP05 — Extend the same jobs to regular GPU and NPU work

**Depends on SP01 and the existing G22 and PC11 target milestones.** Use G22's
fixed workgroup reduction as the first GPU analogue of a batched frontier.
Use per-workgroup shared scratch and barriers with explicit tail handling.
Use separate dispatches and queue dependencies for cross-workgroup reduction
or joins. Compare WGSL/wgpu with the planned MLIR accelerator path only when
both are available on the same target and numeric profile. Keep device leases
through confirmed completion and use bounded submission across devices.
Measure CPU/GPU overlap with independent work and a verified hand-off for
dependent work. Try a persistent ring kernel only if a pinned device supports
the required synchronization and profiling justifies it. NPU placement uses
the named operator and DMA contract from PC11, with its own completion and
instruction boundaries.

**Exit.** A common job graph drives the SafestOS CPU host and the selected
device adapters. A serial oracle, delayed-completion tests and a physical
execution record cover the same semantics. Keep barrier, launch, numeric and
driver assumptions with the device proof. [GPU execution plan](gpu/NEXT_STEPS.md),
[NPU boundary](lean4mm0.md#pc11--define-the-first-npu-proof-branch-and-its-opaque-cut).

**First parallel patch.** After the paired clamp can run under Cranelift,
deliver SP00's serial map-and-sum fixture and reuse its oracle unchanged in
SP01 and SP02. Use the existing Rust bridge tests with
`cargo test --locked --manifest-path safestos/cranelift/Cargo.toml` and run
Dune through the repository's Nix devshell. Preserve the existing bridge
freshness checks and rebuild its release artifact when the bridge changes.
